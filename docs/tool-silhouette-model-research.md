# Alternatives for tool-silhouette tracing

Research date: 2026-10-05. **Recommendation:** for an already-integrated alternative, benchmark fal/Replicate BiRefNet and local BiRefNet Lite against Gemini. For a new segmentation approach, the most promising candidate is **fal SAM 3 image**: its API accepts text/point/box prompts and can return separate masks, better matching object-by-object tracing than generic background removal. It is available from fal but is **not currently wired into Tracefinity**. If testing image generators through OpenRouter, shortlist `openai/gpt-image-2.5-sunburst` and `bytedance-seed/seedream-5-0-flash`; treat all as hypotheses, not proven upgrades. No source establishes better tool-mask quality than Gemini.

## What matters for this task

Tracefinity perspective-corrects the photo, asks the tracer for a black/white silhouette mask at target dimensions, then extracts contours into polygons. For this pipeline, spatial fidelity, thin-detail retention, clean genuine gaps, and separating touching tools matter more than general image-generation quality. Existing tracing docs call out thin tools, reflective/transparent tools, and overlapping tools as failure cases. A visually plausible generated image is not necessarily an aligned, binary mask.

## Shortlist and fit

**fal SAM 3 image** (`fal-ai/sam-3/image`) — strongest new segmentation candidate to evaluate. fal describes it as promptable image/video segmentation; its image API accepts text, point, or box prompts and can return multiple masks with optional scores and boxes, at $0.005/request. This could help isolate individual overlapping tools, though it requires a new Tracefinity adapter and a way to select/prompt each tool; the published example returns a 1024×1024 mask, so exact alignment still needs validation. [fal SAM 3 API](https://fal.ai/models/fal-ai/sam-3/image/llms.txt)

OpenRouter's Image API supports reference images and provides a live image-model catalog and per-endpoint capabilities; its docs recommend checking endpoint-level support and note fixed tiers/normalized sizes. Tracefinity's OpenRouter config currently expects a model routed to `image_generation` through its Responses endpoint, so catalog presence alone does not prove compatibility with the currently configured request path. [OpenRouter Image Generation docs](https://openrouter.ai/docs/guides/overview/multimodal/image-generation) · [Tracefinity tracing docs](usage/tracing.md)

**Do not prioritize** text-only image generators: the source photo is essential. Also avoid assuming an image-to-image “design layer” model is a segmentation substitute; the catalog's description is about decomposing flattened design artwork, not photographic tools.

## Recommendation and benchmark gate

1. Compare **Gemini**, the already-integrated **BiRefNet** routes (fal v2 and local Lite; Replicate if useful), and—if a new adapter is in scope—**fal SAM 3**. SAM 3 is the most promising architecture change because it supports prompted, separate object masks; it is not a drop-in replacement.
2. If generative alternatives are still worth testing, try **GPT Image 2.5 Sunburst** and **Seedream 5.0 Flash** through a compatible OpenRouter image-generation path. Measure whether exact registration can be recovered; don't accept dimension matching alone as pixel alignment.
3. Use identical perspective-corrected inputs, prompts where applicable, and post-processing. Score mask IoU/boundary error and review per-image failures, especially **thin shafts/needles, reflective or low-contrast metal, shadows/tinted sheet, genuine plier/jaw gaps, touching or overlapping tools**, and whether each output preserves separate tool contours. Record dimensions, latency, cost, and failures. Select only after a paired benchmark; public descriptions and benchmark scores for general image quality cannot settle this task.

## Gemini 4 context

Gemini 4 Argon was announced, but the separate research note found no public Google API model ID and no OpenRouter listing on 2026-10-05. Do not infer a routable model slug from the announcement. See [Gemini 4: existence and OpenRouter availability](gemini-4-openrouter-research.md).
